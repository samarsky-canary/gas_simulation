# Проверка соответствия текущей ML-версии

Дата проверки: 2026-05-14.

## Короткий вывод

Текущий прототип зафиксирован как RUL-прогноз: симулятор формирует телеметрию и целевые метки, feature builder строит диагностические признаки, RandomForest baseline прогнозирует RUL, а гибридный слой выбирает итоговый RUL с учетом аналитической оценки и качества данных.

## Что входит в текущий контур

```text
симулятор
-> фиксированный датасет
-> feature builder
-> RandomForest ML baseline
-> confidence
-> RUL_fused_h + rul_source
-> графики и таблица событий обслуживания
```

## Что проверено методически

1. Датасет имеет фиксированный контракт колонок.
2. Входы ML-моделей ограничены наблюдаемыми и производными признаками.
3. Скрытые и целевые переменные не используются как входы.
4. `deltaP_norm_kPa` нормируется по расходу.
5. `RUL_oracle_h` используется как synthetic target для оценки качества.
6. Гибридный слой учитывает качество данных, согласованность ML и аналитического RUL, итоговое доверие и выбирает источник RUL.
7. ML baseline обучается на корпусе из независимых `run_id`, а test состоит из других прогонов.

## Реализованные блоки

- Симулятор эксплуатации фильтра.
- Экспорт CSV/Parquet.
- Feature builder.
- RandomForestRegressor для `RUL_oracle_h`.
- Гибридный RUL fusion.
- Интерактивные Plotly-графики.
- Таблица событий обслуживания по устойчивому пересечению RUL-порогов.

## Текущий смысл гибридной модели

ML-модель отвечает за прогноз RUL. Аналитическая модель используется как физически интерпретируемый baseline и fallback. Гибридный слой проверяет качество данных, согласованность прогнозов и выбирает итоговый RUL.

Назначение планового и срочного обслуживания не выполняется внутри гибридного слоя. UI рассчитывает события обслуживания отдельно по `RUL_ml_h`, `RUL_analytic_h` и `RUL_fused_h`.
