# Правила гибридного RUL и обслуживания

Документ фиксирует актуальные правила текущей версии. Отдельный пороговый baseline
удален из конвейера; состояние фильтра берется из симулятора, а события обслуживания
рассчитываются в UI по RUL-порогам.

Актуальные реализации:

- `src/hybrid/decision_engine.py` - гибридный выбор итогового RUL и доверия.
- `src/visualization/maintenance_events.py` - события планового и срочного обслуживания.
- `src/simulator/labels.py` - состояние фильтра и аналитический RUL.

## 1. Пороги

| Параметр | Смысл |
|---|---|
| `dp_warn_kpa` | Порог предупредительного состояния фильтра. |
| `dp_crit_kpa` | Порог критического состояния фильтра. |
| `planned_maintenance_rul_h` | RUL-порог планового обслуживания. |
| `urgent_maintenance_rul_h` | RUL-порог срочного обслуживания. |
| `stable_degraded_rul_h` | Минимальная длительность устойчивого нахождения ниже порога. |

## 2. Гибридный RUL

Гибридный слой получает `RUL_ml_h`, `RUL_analytic_h`, признаки качества данных и
диагностические признаки перепада давления.

На выходе формируются:

- `RUL_fused_h` - итоговая оценка остаточного ресурса;
- `rul_source` - источник итоговой оценки;
- `confidence_data` - доверие к данным;
- `confidence_model` - доверие к ML-прогнозу;
- `confidence_consistency` - согласованность ML и аналитического RUL;
- `confidence_total` - итоговое доверие к прогнозу.

Основная логика:

1. Если качество данных низкое, ML блокируется и используется аналитический fallback.
2. Если ML и аналитический RUL сильно расходятся, выбирается консервативный минимум.
3. Если прогнозы согласованы и данные надежны, используется ML-прогноз.
4. Итоговое доверие понижается при пропусках, всплесках и расхождении прогнозов.

## 3. События обслуживания

UI рассчитывает события отдельно для:

- `RUL_ml_h`;
- `RUL_analytic_h`;
- `RUL_fused_h`.

Событие обслуживания фиксируется, когда RUL устойчиво находится ниже расширенного
порога:

```text
effective_threshold = maintenance_threshold_h + stable_degraded_rul_h
```

Так ожидание устойчивости не сдвигает событие позже требуемого RUL-порога.

Для планового обслуживания используется `planned_maintenance_rul_h`, для срочного -
`urgent_maintenance_rul_h`.
