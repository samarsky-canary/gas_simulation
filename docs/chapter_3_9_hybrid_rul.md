# 3.9. Реализация гибридного RUL

Гибридный слой реализован в модуле `src/hybrid/decision_engine.py`. Его задача - объединить три источника информации: ML-прогноз `RUL_ml_h`, аналитическую оценку `RUL_analytic_h` и качество входных данных. На основе этих данных решатель вычисляет доверие к данным, доверие к модели, согласованность ML и аналитики, выбирает итоговый RUL и формирует действие по обслуживанию.

На вход `build_hybrid_decisions(...)` подаются канонический датасет, таблица инженерных признаков и таблица ML-предсказаний. Решатель объединяет их по `timestamp`, а при наличии нескольких прогонов - по `run_id` и `timestamp`. После этого для каждой временной точки рассчитываются `confidence_data`, `confidence_model`, `confidence_consistency` и итоговое `confidence_total`. Итоговый `RUL_fused_h` выбирается по правилам: использовать ML при высоком доверии, взять консервативный минимум при среднем доверии или перейти к аналитическому fallback при низком доверии, пропусках ML либо вето качества данных.

Выход гибридного слоя содержит не только численную оценку, но и готовое решение: `RUL_fused_h`, `rul_source`, `confidence_total`, `action`, `priority`, `due_time_h`, `rule_trace` и `explanation`. Это позволяет использовать результат не как "черный ящик", а как объяснимую рекомендацию для инженера или оператора.

| Функция | Назначение |
|---|---|
| `build_hybrid_decisions(cfg, dataset, features, ml_predictions)` | Основная функция гибридного слоя. Объединяет датасет, признаки и ML-прогнозы, затем для каждой строки рассчитывает итоговый RUL, доверие, действие, приоритет, срок и объяснение. |
| `_prepare_inputs(dataset, features, ml_predictions)` | Подготавливает входную таблицу для решателя: добавляет признаки качества окна, тренд перепада, время выше warning-порога и ML-прогноз `RUL_ml_h`. |
| `_decide_row(cfg, row)` | Применяет гибридную логику к одной временной точке. Считает confidence, вызывает выбор итогового RUL, применяет правила действий и возвращает выходные поля решения. |
| `_confidence_data(row, hard_veto)` | Оценивает доверие к данным по `quality_code`, физическим нарушениям и `missing_rate_1h`. При hard veto доверие резко снижается, чтобы заблокировать прямое использование ML. |
| `_confidence_model(row)` | Оценивает применимость ML-прогноза. Если `RUL_ml_h` отсутствует или отрицательный, доверие к модели равно нулю; иначе используется базовый уровень доверия. |
| `_confidence_consistency(cfg, row)` | Сравнивает `RUL_ml_h` и `RUL_analytic_h`. Чем сильнее относительное расхождение между ML и аналитикой, тем ниже доверие к согласованности. |
| `_fuse_rul(row, confidence_total, confidence_consistency, data_hard_veto)` | Выбирает `RUL_fused_h` и `rul_source`. Возможные источники: `ml_baseline`, `conservative_min`, `analytic_fallback`, `analytic_data_veto`, `unavailable`. |
| `_apply_rules(cfg, row, ...)` | Назначает итоговое действие, приоритет, срок выполнения и объяснение. Учитывает качество данных, опасно низкое выходное давление, critical-состояние, расхождение прогнозов и пороги обслуживания. |
| `_has_physical_violation(row)` | Проверяет физически невозможные наблюдения: `P_out > P_in`, отрицательный `deltaP_kPa` или отрицательный расход. Такие ситуации блокируют доверие к ML-решению. |
| `_is_low_outlet_pressure(cfg, row)` | Проверяет опасно низкое выходное давление. При выполнении условия и достаточном качестве данных может привести к действию `shutdown_request`. |
| `_is_rul_below(value, threshold)` | Безопасно сравнивает RUL с порогом обслуживания, учитывая возможные пропуски. |
| `_due_time(rul_fused, horizon_h)` | Рассчитывает срок выполнения действия как минимум между итоговым RUL и нормативным горизонтом обслуживания. |
| `_fallback_value(primary, secondary)` | Выбирает первый доступный RUL при fallback-логике: обычно аналитический RUL, а при его отсутствии - ML-прогноз. |
| `export_hybrid_decisions(decisions, output_dir)` | Сохраняет результаты гибридного слоя в Parquet/CSV, Markdown-описание логики и JSONL-пакеты объяснений. |
| `_decision_package(row)` | Собирает структурированный пакет объяснения решения: состояние, качество, ML/analytic/fused RUL, confidence, действие, rule trace, ключевые признаки и практические рекомендации. |
| `_write_decision_packages_jsonl(decisions, path)` | Сохраняет машинно-читаемый журнал объяснений для каждой временной точки в формате JSON Lines. |
| `_description()` | Генерирует Markdown-описание гибридной логики: контур обработки, источники RUL, основные действия, группы правил и выходные файлы. |
